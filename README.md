# إسهام | Esham Platform

مستودع واحد منظّم للفرونت والباك وخدمات الذكاء الاصطناعي. واجهة React/Vite الحالية موجودة بالكامل في `frontend/`، والباك والـAI المستقل هيكل جاهز لبدء التطوير؛ لا توجد خدمات خادم منفذة حتى الآن.

## تقسيم المشروع

```text
esham/
├── frontend/                 # الموقع الحالي بكامل كوده وملفاته
│   ├── src/
│   ├── public/
│   ├── scripts/
│   ├── tests/
│   ├── index.html
│   ├── package.json
│   ├── package-lock.json
│   ├── .env.example
│   └── .env.production
├── backend/                  # API وقواعد الأعمال وقاعدة البيانات — يبدأ لاحقًا
│   ├── src/
│   │   ├── config/
│   │   ├── modules/
│   │   ├── middleware/
│   │   ├── integrations/
│   │   └── jobs/
│   ├── database/migrations/
│   └── tests/
├── ai/                       # خدمة AI مستقلة مستقبلًا
│   ├── src/
│   ├── models/
│   └── tests/
├── docs/                     # التصميم المعماري وعقود الربط والتوثيق المشترك
├── package.json              # أوامر تشغيل الفرونت من جذر المستودع
├── netlify.toml
└── vercel.json
```

فحص CLIP المحلي الحالي بقي في الفرونت؛ مجلد `ai/` مخصص لخدمة الخادم المستقبلية. تنظيم المستودع لا ينقل أو يحذف بيانات المتصفح.

## التشغيل من جذر المشروع

استخدم Node.js 22.12 أو أحدث؛ ملف `.nvmrc` يحدد سلسلة Node 22. من مجلد المشروع الرئيسي:

```bash
npm install
npm run dev
```

تثبيت الجذر يشغّل `npm ci` داخل `frontend/` تلقائيًا حسب ملف القفل الخاص به. الأوامر التالية توجّه العمل إلى الفرونت:

```bash
npm test
npm run build
npm run preview
```

نسخة الإنتاج تُنشأ في **`frontend/dist`**. لتحديد نفس المنفذ الذي كنت تستخدمه حتى تبقى بيانات المتصفح على نفس أصل الموقع:

```bash
npm run dev -- --port 5174
```

يبقى التشغيل مباشرةً من `frontend/` ممكنًا بأوامر npm المعتادة. لإعادة تثبيت اعتماداته من الجذر استخدم `npm run setup`. عند إضافة مكتبة للفرونت:

```bash
npm --prefix frontend install library-name
```

## الإعدادات والربط

- إعدادات الفرونت في `frontend/.env.local`؛ انسخ إليها `frontend/.env.example` واضبط `VITE_API_BASE_URL` عند توفر الباك.
- `frontend/.env.production` يفعّل قائمة الأدمن المؤقتة لعرض المشروع. يمكن تعطيلها بتغيير `VITE_ADMIN_PREVIEW` إلى `false` وإعادة البناء.
- إعدادات الباك المستقبلية في `backend/.env`، وإعدادات AI في `ai/.env`. الأمثلة في كل مجلد؛ لا تضع الأسرار في متغيرات `VITE_` أو في Git.
- لم يُفرض إطار عمل أو لغة للباك أو AI؛ يقررها الفريق قبل تنفيذ الخدمات وإضافة ملفات الاعتمادات الخاصة بها.

راجع [توثيق الفرونت والمكتبات](frontend/README.md)، و[خطة الباك](backend/README.md)، و[خطة AI](ai/README.md)، و[تنظيم المشروع](docs/architecture.md)، و[عقود الباك](docs/backend-contract.md).

## النشر

**Netlify:** إعداداته في `netlify.toml` بالجذر. أمر البناء `npm run build` ومجلد النشر `frontend/dist`. ملف إعادة التوجيه بقي في `frontend/public/_redirects` ويُنسخ إلى الإنتاج لفتح مسارات الموقع مباشرةً. قاعدة المشروع هي جذر المستودع.

**Vercel:** إعداداته في `vercel.json` بالجذر؛ تم تعديل مجلد الناتج إلى `frontend/dist`. اترك Root Directory على جذر المستودع وأعد النشر بعد رفع التنظيم.

إذا تنشر يدويًا على Netlify، ارفع **`frontend/dist`** بعد البناء. استضافة الفرونت لا تشغّل الباك أو AI المستقبليين؛ لهما إعداد نشر مستقل بعد التنفيذ.

## Git والعمل مع الفريق

```bash
git pull origin main
npm install
npm run dev
```

لحفظ ورفع تنظيم المجلدات من الجذر، بعد مراجعة الملفات:

```bash
git status
git add -A
git commit -m "Organize platform into frontend backend and AI directories"
git push origin main
```

`git add -A` مهم لاحتساب نقل الملفات وحذف مساراتها القديمة. Git يتتبع النقل ويحافظ على تاريخ الكود. الاعتمادات والبناء ونتائج الفحص وملفات الأسرار مستثناة عبر `.gitignore`.

## ملاحظات النسخة الحالية وبيانات العرض

أُزيلت من واجهات الموقع الملاحظات التي تصف المشروع بأنه تجريبي أو جامعي، ونُقلت إلى هذا القسم. إزالة هذه العبارات تغيير في العرض فقط، ولا تعني اكتمال خدمات الخادم أو اعتماد البيانات والسياسات.

- المشروع بدأ كمشروع جامعي؛ بيانات الدورات والتقييمات والإشعارات والإحصاءات والمديرين المبدئية بيانات توضيحية، وبعض المؤشرات ثابتة.
- التفضيلات والحسابات المحلية والتقدم والمهام والتقييمات والردود والنقاط والبلاغات والتحذيرات والمسودات محفوظة في المتصفح. الفيديوهات والمرفقات محفوظة على الجهاز عبر IndexedDB، ولم تُرفع إلى خادم؛ المزامنة بين المستخدمين والأجهزة تحتاج الباك.
- تغيير كلمة المرور وحذف الحساب يحتاجان خدمة الحسابات. تبقى الإجراءات غير المتاحة ورسائل فشلها واضحة، ولا تعرض الواجهة نجاحًا وهميًا.
- قائمة صفحات الأدمن مخصصة للعرض أثناء التطوير، وليست نظام مصادقة أو تفويض. مراجعة الدورات والإجراءات المحلية تحتاج لاحقًا صلاحيات خادم وسجل تدقيق مركزي.
- شهادات الواجهة معاينات؛ اعتمادها وتاريخ الإصدار ورقم التحقق وإصدار شهادات موثقة يحتاج خدمة شهادات تتحقق من الإكمال.
- الشات يعرض إرشادات للمنصة؛ الإجابات العامة وتحليل المرفقات والتخصيص بالذكاء الاصطناعي تحتاج خدمات فعلية. عند عدم توفر الإجابة يظهر تنبيه بعدم التوفر.
- فحص الفيديو المحلي باستخدام CLIP يراجع عينات صور فقط، وقد يخطئ؛ لا يحلل الصوت ولا يمنح اعتماد سلامة للأطفال. يحتاج أول تشغيل تنزيل النموذج، وفرض المراجعة على جميع مسارات النشر يحتاج الباك ومراجعة بشرية.
- الشروط والخصوصية ليست سياسات قانونية معتمدة. تحتوي صفحة الشروط على نصوص مقترحة للعرض عن الحسابات والنقاط والتعلّم وحقوق المحتوى والسلامة والبلاغات، دون وصفها بالتجريبية داخل الواجهة. يجب مراجعتها واعتماد قواعد الحسابات والتسجيل والنقاط وحقوق المحتوى والشكاوى والإلغاء، وتحديد أغراض جمع البيانات والخدمات المستقبلة وفترات الاحتفاظ وحقوق المستخدم ووسيلة التواصل قبل الإطلاق.
- الدعم المباشر وإرسال البريد والتنبيهات للمستخدمين والتحويل المباشر لملفات Office خدمات تحتاج الربط لاحقًا.

هذه الملاحظات للتطوير والتسليم، ولا تظهر كشارات أو تنبيهات عن بيانات تجريبية داخل واجهات الموقع بالعربية أو الإنجليزية.
