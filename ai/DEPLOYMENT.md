# تجهيز وتشغيل خدمات الذكاء الاصطناعي

## ما يعمل الآن

- التشغيل المحلي: خدمة المساعد على 8001 وخدمة الفيديو على 8000، دون تغيير ملفات `backend/`.
- الشات العام للمتعلّم والمدرّب، ومعرفة الموقع ومراجع الكتالوج والتوصيات.
- تحليل TXT وPDF ذي النص القابل للاستخراج: حتى 10MiB، أول 20 صفحة وحتى 16,000 حرف. الملف الأصلي لا يرفع للنموذج؛ يرسل النص المستخرج فقط. يذكر المساعد إذا قرأ جزءًا من الملف. PDF الممسوح ضوئيًا أو المحمي يحتاج OCR/إزالة الحماية خارج هذه الميزة.
- تحليل صور PNG/JPG/WebP/GIF: يصغّر المتصفح الصورة إلى 1280px ويحذف البيانات الوصفية بإعادة ترميزها JPEG، بحد 2MiB للنسخة المرسلة. GIF يمثل أول إطار فقط. تستخدم الصور مفتاح خدمة الرؤية الموجود على الخادم؛ المحادثة النصية تستمر مع مزود الشات المضبوط. لا تظهر أسماء المزودين في واجهة الإجابة.
- `npm run serve` داخل ai يشغّل بوابة واحدة على 8080، والخدمتان خلفها على loopback بمنافذ داخلية عشوائية.
- الزائر غير المسجل يحصل على إجابات معرفة إسهام العامة المملوكة للمشروع دون استدعاء نموذج مدفوع. يُطلب تسجيل الدخول للمحادثة العامة وتحليل المرفقات. الإجابات العامة للزائر محددة بموضوعات الموقع؛ ليست وكيل أعمال ولا بحث ويب.
- التحقق من الجلسة عبر `GET BACKEND_SESSION_URL` الموجود في الباك. يرسل فقط كوكي `Esham.Identity` وأجزاءه، ولا يثق بهوية المتصفح أو دور localStorage. فحص الفيديو للمدرب أو الهايبرد فقط.
- كتالوج المتصفح لا يعتمد كمصدر رسمي في البوابة؛ يستخدم ملف كتالوج عام موثوق من المشغّل عند ضبط `PLATFORM_CATALOG_FILE`، وإلا يبقى فارغًا. لا يتم اختلاق دورات محلية؛ تبقى معرفة الموقع ومراجع Coursera الخارجية متاحة.

## المطلوب من صاحب المشروع للنشر

1. توفير خادم أو استضافة تشغّل Node 22.12+ أو Docker، مع نطاق HTTPS. لا تضع مفاتيح الخدمات في Netlify/Vite كمتغيرات `VITE_*`.
2. تشغيل الباك الحالي وضبط اتصال قاعدة بياناته بواسطة فريقه، ثم التأكد أن `/auth/session` يرجع `{profile:{id,role}, onboardingRequired:false}` بعد الدخول و401 بدونه.
3. وضع الموقع والحسابات والـAI خلف نطاق HTTPS واحد. اجعل `/ai/` يمر للبوابة، و`/auth/` و`/me` للباك. هذا يجعل كوكي الجلسة متاحًا دون السماح بكوكيز الطرف الثالث. مثال Nginx في `deploy/nginx.conf.example` يحتاج وضعه داخل إعداد HTTPS الموجود وتحديد عنوان الباك الحقيقي.
4. ضبط المتغيرات السرية على الخادم: `DEEPSEEK_API_KEY` للشات عند اختيار deepseek، و`GEMINI_API_KEY` للفيديو والصور. اضبط `CHAT_PROVIDER` والنماذج كما في `.env.example`، و`PUBLIC_ORIGIN` و`BACKEND_SESSION_URL` بالقيم الحقيقية. HTTP الداخلي مسموح فقط عند ضبط `ALLOW_INTERNAL_HTTP=true` لشبكة خوادم خاصة موثوقة.
5. بناء الفرونت مع:

```env
VITE_ASSISTANT_API_URL=/ai/assistant
VITE_VIDEO_REVIEW_API_URL=/ai
```

ثم `npm run build`. إذا كان الموقع الحالي على Netlify فقط دون بوابة وحسابات منشورة، فإن رفع الفرونت وحده لن يشغّل خدمات AI العامة.

6. بعد النشر: جرّب سؤال موقع من زائر (ينجح)، سؤالًا عامًا من زائر (يطلب الدخول)، مرفقًا من زائر (401)، ثم الدخول واختبار النص والمرفقات، ومحاولة فحص فيديو بحساب متعلم (403) ومدرّب (يصل للخدمة). جرّب تسجيل الخروج والتأكد من عدم استمرار الوصول المحمي.

### تفعيل DeepSeek

احصل على مفتاح من منصة المطورين وأضفه إلى `ai/.env` المحلي فقط، مع `CHAT_PROVIDER=deepseek` و`DEEPSEEK_MODEL=deepseek-flash`، ثم أعد تشغيل المساعد. `ai/.env.example` مثال عام ويجب أن تبقى جميع المفاتيح فيه فارغة. رمز402 يعني رصيد API غير كافٍ، و401 مفتاحًا غير صالح؛ واجهة الدردشة المجانية منفصلة عن رصيد API. يمكن اختيار `CHAT_PROVIDER=google` صراحة إذا أردت استخدام الخدمة الأخرى المتاحة؛ لا يوجد تحويل خفي تلقائي بين المزودين.

## Docker

من جذر المستودع:

```powershell
docker build -f ai/Dockerfile -t esham-ai .
docker run --env-file ai/.env -e PORT=8080 -p 127.0.0.1:8088:8080 esham-ai
```

يجب تعديل قيم النشر محليًا داخل ملف الأسرار قبل التشغيل، أو استخدام مدير أسرار الاستضافة. المنفذ 8088 يبقى خاصًا خلف HTTPS reverse proxy. بناء الصورة ينزّل نسخة Kaggle رقم 1 وينظفها ويتحقق من SHA-256 للـCSV الأصلي، ويتوقف إذا اختلف المصدر. لا ينسخ ملفات الأسرار أو الباك إلى الصورة.

تم التحقق من كود البوابة باختبارات HTTP محلية؛ لم تختبر حاوية Docker الفعلية في جلسة التطوير لأن محرك Docker لم يكن يعمل. ولم يختبر نطاق الإنتاج أو جلسة الباك الحقيقية في بيئة منشورة؛ لا تعتبر القوالب دليل نشر ناجح.

## الحدود والاختبارات

- بوابة المحادثة تقبل JSON حتى 4MiB لصور الشات المصغرة؛ نص السؤال 2000 حرف، تاريخ النموذج 6 رسائل، النص المستخرج 16000 حرف. الطلبات الفعالة للبوابة محدودة بـ20؛ لكل حساب 10 طلبات محادثة و3 فيديو بالدقيقة؛ الزوار مجتمعون حتى30 طلبًا بالدقيقة. حدود الخدمتين الداخلية الإجمالية تبقى فعالة كذلك، لذا لا يمثل ذلك تجهيزًا للتوسع الأفقي.
- الإلغاء والمهل والحدود موجودة. لا يحفظ الخادم الأسئلة والملفات أو يطبع المفاتيح. لا تستخدم سجلات reverse proxy لحفظ أجسام الطلبات أو الكوكيز.
- فحص الفيديو حتى20MiB و600 ثانية. النتيجة إرشادية؛ قرار النشر الرسمي لا يصدر من البوابة. لا تغيّر نتيجة محلية أو تنشر درسًا اعتمادًا على ادعاء المتصفح.

```powershell
npm test
npm --prefix ai test
python -m unittest discover -s ai/tests -p test_*.py
npm run build
npm --prefix ai run evaluate
# اختياري: يستدعي الخدمات المدفوعة بالمفاتيح المحلية
npm --prefix ai run evaluate -- --live
```

التقرير المحلي `artifacts/evaluation/ai-readiness.json` مستثنى من Git ولا يحتوي مفاتيح. فحوصات الاسترجاع والمحادثة تثبت حالات محددة فقط، وليست قياس دقة علميًا. لتقييم الفيديو على محتوى ممثل، جهّز مقاطع مسموح استخدامها مع تقييم بشري مستقل:

```json
[{"id":"example-1","path":"C:/consented-clips/example.webm","duration":8,"mimeType":"video/webm","expectedStatus":"review","labelNotes":"Human reviewer notes and expected reason"}]
```

ثم `npm --prefix ai run evaluate -- --video-manifest C:/path/labels.json`. الملف يرسل الفيديوهات المحددة لخدمة الفحص؛ لا تشغّله على ملفات أشخاص دون إذن. يلزم توفير هذه المقاطع والتقييمات لقياس الدقة، ولا يمكن اختلاق نتيجة موثوقة من فيديو واحد.

## المتبقي المتعلق بقاعدة البيانات وتكاملها

- حفظ الدورات والأقسام والدروس والمهام والتقييمات والوسائط والتقدم بقاعدة البيانات بدل مخزن المتصفح، ثم توفير كتالوج الخادم للـAI.
- تسجيل خصم20 نقطة للمتعلم وإضافة20 للمدرب ومنحة البداية مرة واحدة ضمن معاملات ذرية ومنع ازدواج التسجيل.
- حفظ سجل التعلّم والتدريس عند تغيير نوع الحساب، والتحقق من الصلاحيات من الخادم.
- تخزين فيديو الخادم مع بصمة محتواه ونتيجة الفحص وتاريخه ومدته؛ ربط القرار بالنسخة الفعلية ومنع نشر أو استبدال الفيديو دون فحص صالح، وحفظ قرارات المراجعة البشرية والاعتراضات.
- حفظ المحادثات ومراجعها وصلاحياتها ومدد الاحتفاظ بها إذا أريد مزامنتها بين الأجهزة؛ السجل الحالي خاص بجلسة التبويب.
- إصدار الشهادات والتحقق منها من بيانات إكمال موثوقة، مع حفظ الشهادات والبلاغات والإشعارات وسجل تدقيق الإدارة.
